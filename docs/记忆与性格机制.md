# 记忆与性格机制（共生人生 · 地基）

> 本文档说明 Cochpia 已落地的「记忆形成」与「性格形成」两大系统的设计模式与代码运行方式。
> 它们是《共生人生》游戏方案中"规则引擎当大脑、LLM 当嘴"的地基：日常沉淀零成本，人格变化可审计、可回滚。
> 更新日期：2026-08-15

## 一、记忆形成：三个模式 + 五个工具

### 模式 1：自动沉淀（聊完自动判断要不要记）

不是每条消息都记，而是启发式判断"值不值得长期记住"。

代码：`server/auto-memory.js`

```js
// 是否值得沉淀为长期记忆
shouldRemember(text) {
  if (text.length < 12) return false;           // 太短不记
  const significant = /(记住|喜欢|讨厌|重要|承诺|约定|生日|想要|害怕|梦想|决定|计划)/.test(text);
  return text.length >= 40 || significant;      // 够长 或 含关键词
}

// 情感坐标：效价(正/负) + 唤醒度(激动程度)
analyzeMessage(text) {
  // 命中正向词 +0.2/个，负向词 -0.2/个 → valence ∈ [-1, 1]
  // 感叹号/问号越多 → arousal 越高
}
```

### 模式 2：情感衰减（记忆随时间变淡）

代码：`server/memory-service.js` 的 `decayedStrength()`

```
强度 = 原始强度 × e^(-λ·天数)
λ = 0.02 + 0.08 × (1 - 重要性)
```

| 重要性 | 半衰期 |
|--------|--------|
| 1.0 | 约 35 天 |
| 0.0 | 约 7 天 |

越重要的记忆忘得越慢，对应"情绪给记忆染色、重要的事更持久"。

### 模式 3：检索排序（上下文里召回什么）

代码：`memory.breath(query)`

```
排序分 = 0.7 × 相关度(关键词命中率) + 0.3 × 衰减强度
```

取 Top N 注入下一次对话，让 AI "记得该记得的"。

### 五个工具（记忆边界）

| 工具 | 含义 | 代码方法 | 说明 |
|------|------|---------|------|
| breath | 呼吸·检索 | `breath(query, limit)` | 按相关度 + 衰减强度排序 |
| hold | 持有·写入 | `hold(input)` | 存长期记忆（summary/valence/arousal/importance） |
| dream | 梦·回放 | `dream(limit)` | 按衰减强度排序浏览 |
| grow | 成长·沉淀 | `grow(input)` | 生成成长证据（draft 态） |
| trace | 追溯·查证 | `trace(id)` | 查单条证据 |

辅助：`updateEvidence(id, status)` 确认/驳回证据；`revoke(id)` 撤销记忆；`exportMemories()` 导出。

## 二、性格形成：一个版本机 + 证据确认制

### 设计：人格是"长"出来的，不是"设置"的

代码：`server/psychology.js` —— 7 个可度量维度，锚定心理学理论：

| 维度 | key | 理论来源 | 基线 |
|------|-----|---------|------|
| 安全感 | security | 依恋理论 | 0.6 |
| 回应性 | responsiveness | 依恋理论 | 0.7 |
| 共同调节 | coregulation | 多迷走神经理论 | 0.6 |
| 激活度 | activation | 多迷走神经理论 | 0.5 |
| 自主支持 | autonomy | 自我决定论 | 0.7 |
| 胜任肯定 | competence | 自我决定论 | 0.6 |
| 归属联结 | relatedness | 自我决定论 | 0.7 |

另有 5 个「互动氛围」预设（安全港湾 / 温柔同行 / 平静调节 / 好奇探索 / 安静守护），通过 system prompt 注入语气。

### 核心机制：变更必须"有证据 + 有版本 + 可回滚"

代码：`server/personality.js`

```js
applyPersonalityChange(personality, history, { evidenceId, proposedChange, action }) {
  // 1. 校验证据和变更（无 traitKey / delta 非法 / delta=0 → 拒绝，返回 null）
  // 2. 找到对应维度，delta 累加（clamp 到 0~1）
  // 3. version + 1，旧版本快照压入 history
  // 4. 返回 { personality: 新人格, history: 新历史 }
}
```

三个铁律：

1. **显式变更** —— 没有证据 ID 的变更一律拒绝。
2. **版本可审计** —— 每次变化 `version+1`，快照进 `personalityHistory`。
3. **可回滚** —— `POST /api/personality/rollback` 回到任意历史版本，并写审计记录。

## 三、完整运行链路（从聊天到人格变化）

```
用户发消息
   ↓
POST /api/chat/stream            (server/index.js)
   ↓
① memory.breath(消息内容)          ← 检索相关记忆
   ↓
② buildRuntimeContext({            ← 组装 LLM 上下文 (server/runtime-context.js)
     messages,                     ← 最近 20 条（去掉被替代的）
     personality,                  ← 人格版本 + traits
     recalled,                     ← 检索到的记忆
     summary, persona,             ← 会话摘要、人格
     atmosphere, upcomingEvents     ← 氛围、临近事件
   })
   ↓
③ LLM 流式回复（SSE：meta → text → done）
   ↓
④ 回复完成后自动沉淀：
   if (shouldRemember(用户消息)) {
     held = memory.hold(...)       ← 存一条事件记忆
     memory.grow({                 ← 生成成长证据（draft）
       claim: 'Cochpia 正在学习把共同经历纳入后续回应。',
       evidence: `本次对话形成事件记忆 ${held.id}`,
       proposedChange: { traitKey: 'warmth', delta: 0.005 }
     })
   }
   ↓
⑤ 前端「成长证据时间线」用户确认/驳回
   ↓
PATCH /api/growth/evidence/:id  {status:'confirmed'}
   ↓
⑥ reviewEvidence() → applyPersonalityChange()
    人格维度真实变化，version+1，写审计
   ↓
⑦ 新人格注入下一次对话的 runtimeContext → 循环
```

| GET | `/api/memory/overview` | 记忆概览（数量 + 最近记忆） |

## 六、一句话总结

> **记忆**：聊完自动判断沉淀 → 情感坐标染色 → 时间衰减 → 检索时按"相关度 + 强度"召回。
> **性格**：聊天只"提出证据"（draft），用户"确认"才真正改变人格，每次变化都升版本、留快照、可回滚。
> **闭环**：`聊天 → 记忆 + 证据 → 用户确认 → 人格版本+1 → 新人格影响下一次聊天`。

## 七、给非技术同学的白话版

- **记忆**：像人会"记住重要的、忘掉不重要的"。聊得够深、或者说到喜欢/承诺/生日这类关键词，Cochpia 会自动记下来；记得越久越淡，重要的事淡得慢。
- **性格**：Cochpia 不会"突然变"。每次聊天它只**悄悄写一条"成长小纸条"**（证据），你点了"确认采纳"，它才真的朝那个方向长一点，并且每次变化都留了"历史快照"，随时能退回之前的版本。
- **为什么这么设计**：防止 AI 人格被一次对话带偏，也让用户始终能"看得到、管得住"它的成长，符合产品"可验证成长"的定位。
