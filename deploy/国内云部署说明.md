# Cochpia 国内云部署路线

本项目适合先部署为一个应用服务，数据库使用云厂商托管 PostgreSQL。这样前端、API 和 MCP 入口由同一个 HTTPS 域名提供，降低零基础部署复杂度；数据库不开放公网端口。

## 推荐资源

- 腾讯云轻量应用服务器或 CVM：运行 Cochpia Docker 容器。
- 腾讯云 TencentDB for PostgreSQL：保存账号、对话和记忆数据。
- 腾讯云 COS：后续保存头像、语音、图片和导出文件。
- 腾讯云 DNSPod：管理域名解析。
- 腾讯云 WAF/CDN：正式商业流量增加后再接入。
- GitHub Private Repository：保存代码，不保存用户数据和密钥。

## 第一阶段规格

- 应用服务器：2 vCPU / 4 GB RAM / 40 GB 系统盘起步。
- PostgreSQL：高可用托管版优先，开发阶段可使用基础规格。
- 一个主域名，例如 `cochpia.example.com`。
- 生产环境只开放 TCP 22（限管理 IP）和 TCP 80/443；应用端口 8787 不直接对公网开放。

## 生产环境变量

在云服务器上保存到 `/opt/cochpia/.env`，不要提交到 GitHub：

```env
NODE_ENV=production
PORT=8787
CLIENT_ORIGIN=https://cochpia.example.com
AUTH_MODE=required
STORAGE_PROVIDER=postgres
DATABASE_URL=postgresql://USER:PASSWORD@PRIVATE_DATABASE_HOST:5432/DATABASE
DATABASE_SSL=true
DATABASE_POOL_MAX=10
MODEL_PROVIDER=deepseek
MODEL_DEEPSEEK_API_KEY=server-only-secret
MODEL_DEEPSEEK_NAME=deepseek-chat
MEMORY_MODE=local
```

`DATABASE_URL`、模型 API Key、JWT 密钥和 MCP Token 只能存在于服务器环境变量或云密钥管理服务中。它们不能放入前端变量、Docker 镜像或 GitHub。

## 部署步骤

1. 在国内云厂商创建服务器和托管 PostgreSQL，数据库绑定到私网或安全组。
2. 在服务器安装 Docker，并创建 `/opt/cochpia`。
3. 从 GitHub 拉取私有仓库。
4. 创建 `/opt/cochpia/.env`，填入真实生产变量。
5. 构建镜像：`docker build -t cochpia:production .`
6. 启动服务：`docker run -d --name cochpia --restart unless-stopped --env-file /opt/cochpia/.env -p 127.0.0.1:8787:8787 cochpia:production`
7. 使用 Caddy 或 Nginx 将域名反向代理到 `127.0.0.1:8787`，自动配置 HTTPS。
8. 首次启动前，执行本地数据迁移：`npm run migrate:postgres`。如果没有本地历史数据，应用会自动创建基础状态表。
9. 检查 `https://cochpia.example.com/api/health`，必须返回 `ok: true`、`storageProvider: postgres` 和真实模型的 `modelReady: true`。
10. 完成注册、登录、刷新页面、跨设备登录、发送消息、查看记忆和删除记忆验收。

## 上线前禁止事项

- 不要使用 `AUTH_MODE=off`。
- 不要使用 `STORAGE_PROVIDER=json`。
- 不要使用 `MODEL_PROVIDER=mock`。
- 不要把 PostgreSQL 端口 5432 暴露公网。
- 不要把 8787 直接作为生产公网入口。
- 不要把生产 `.env` 上传到 GitHub。

## 当前版本边界

当前应用已经支持按登录用户隔离聚合状态，但仍是单应用实例的 JSONB 状态模型。上线初期适合个人和小规模测试；商业化前应继续迁移到规范化的用户、会话、消息、记忆和审计表，并增加备份恢复、限流、对象存储和监控。
