# Cochpia 真实模型配置说明

这份说明适合不懂编程的用户。完成后，你可以让 Cochpia 使用 OpenAI、DeepSeek、通义千问、智谱 GLM、Kimi、MiniMax、Claude 或 Gemini 等真实模型。

## 先理解一件事

你需要把模型平台提供的 API Key 配置在 Cochpia 的“后端服务”中，而不是填写到聊天页面。

- 聊天页面：只负责选择供应商和模型。
- 后端服务：负责保存配置并代替前端联系模型平台。
- API Key：只放在后端，不能发给别人，也不要放进截图、聊天消息或前端代码。

如果暂时不配置真实模型，Cochpia 仍可以使用“本地 Mock”模式测试界面和聊天流程。Mock 不会产生云端费用，但回答不是来自真实模型。

## 准备工作

你需要准备：

1. 已经安装好的 Cochpia 项目。
2. 一个模型平台账号。
3. 该平台创建的 API Key。
4. 一个该平台实际可用的模型名称。

API Key 通常在模型平台的“API Keys”“密钥管理”或“开发者中心”中创建。不同平台的页面名称可能不同。

## 第一步：打开项目文件夹

打开 Cochpia 项目所在的文件夹：

```text
C:\Users\umi\Documents\ChatGPT\陪伴Cochpia
```

你应当能看到 `package.json`、`client`、`server` 和 `.env.example` 等文件。

## 第二步：创建配置文件

1. 找到文件 `.env.example`。
2. 复制一份文件。
3. 将复制出来的文件改名为 `.env`。
4. 如果系统询问是否确认修改文件扩展名，请选择“是”。

注意：文件名必须是 `.env`，不能是 `.env.txt`。

如果看不到文件扩展名，请在 Windows 文件夹窗口中打开“查看 → 显示 → 文件扩展名”。

## 第三步：填写模型配置

用记事本打开 `.env`。一次只需要启用一个默认模型供应商。

### 示例：配置 DeepSeek

```text
PORT=8787
CLIENT_ORIGIN=http://localhost:5173
MODEL_PROVIDER=deepseek
MODEL_DEEPSEEK_API_KEY=把你的DeepSeek密钥填写在这里
MODEL_DEEPSEEK_NAME=deepseek-chat
MODEL_TIMEOUT_MS=30000
```

把 `把你的DeepSeek密钥填写在这里` 替换为真实密钥，不要保留中文提示文字。

### 示例：配置 OpenAI

```text
MODEL_PROVIDER=openai
MODEL_OPENAI_API_KEY=把你的OpenAI密钥填写在这里
MODEL_OPENAI_NAME=gpt-5
MODEL_TIMEOUT_MS=30000
```

### 示例：配置通义千问

```text
MODEL_PROVIDER=qwen
MODEL_QWEN_API_KEY=把你的通义千问密钥填写在这里
MODEL_QWEN_NAME=qwen-plus
MODEL_TIMEOUT_MS=30000
```

### 其他供应商的写法

供应商名称要转换成大写：

| 页面显示名称 | `MODEL_PROVIDER` | API Key 配置名 | 模型名称配置名 |
|---|---|---|---|
| OpenAI | `openai` | `MODEL_OPENAI_API_KEY` | `MODEL_OPENAI_NAME` |
| DeepSeek | `deepseek` | `MODEL_DEEPSEEK_API_KEY` | `MODEL_DEEPSEEK_NAME` |
| 通义千问 | `qwen` | `MODEL_QWEN_API_KEY` | `MODEL_QWEN_NAME` |
| 智谱 GLM | `glm` | `MODEL_GLM_API_KEY` | `MODEL_GLM_NAME` |
| Kimi | `kimi` | `MODEL_KIMI_API_KEY` | `MODEL_KIMI_NAME` |
| MiniMax | `minimax` | `MODEL_MINIMAX_API_KEY` | `MODEL_MINIMAX_NAME` |
| SiliconFlow | `siliconflow` | `MODEL_SILICONFLOW_API_KEY` | `MODEL_SILICONFLOW_NAME` |
| Anthropic Claude | `anthropic` | `MODEL_ANTHROPIC_API_KEY` | `MODEL_ANTHROPIC_NAME` |
| Google Gemini | `gemini` | `MODEL_GEMINI_API_KEY` | `MODEL_GEMINI_NAME` |

模型名称必须以模型平台当前实际提供的名称为准。页面中的“建议模型”只是参考，不能保证你的账号一定有权限使用。

## 第四步：保存并重启 Cochpia

修改 `.env` 后必须重启服务，配置才会生效。

如果 Cochpia 当前正在运行：

1. 回到运行 Cochpia 的黑色命令窗口。
2. 按 `Ctrl + C` 停止服务。
3. 重新运行项目启动命令。

常用启动命令是：

```powershell
npm run dev
```

不要关闭命令窗口，否则后端服务会停止。

## 第五步：在网页中测试

打开：

```text
http://localhost:5173
```

然后：

1. 点击右上方的模型设置按钮。
2. 找到刚刚配置的供应商。
3. 确认状态显示“已配置”。
4. 点击“测试连接”。
5. 显示“连接成功”后，点击“用于本会话”。
6. 返回聊天页面发送一条消息。

每个会话可以单独选择模型。切换会保存到当前会话，重新打开该会话时仍会使用之前的选择。

## 常见状态说明

### 显示“未配置”

通常是以下原因之一：

- `MODEL_PROVIDER` 写错。
- API Key 配置名写错，例如把 `MODEL_DEEPSEEK_API_KEY` 写成了 `DEEPSEEK_API_KEY`。
- 模型名称配置为空。
- `.env` 实际上被保存成了 `.env.txt`。
- 修改配置后没有重启后端。

### 显示 `MODEL_NOT_CONFIGURED`

说明后端没有找到完整的 API Key 或模型名称。请检查 `.env` 文件名、变量名称和重启步骤。

### 显示 `MODEL_CONNECTION_FAILED`

说明配置已经被读取，但真实请求失败。可能原因包括：

- API Key 错误或已经失效。
- 账户余额不足或没有模型权限。
- 模型名称写错。
- 网络无法访问模型平台。
- 模型平台暂时不可用。

### 显示模型不存在

请打开对应模型平台的模型列表，复制当前可用的模型名称，替换 `MODEL_<PROVIDER>_NAME` 的值，然后重启 Cochpia。

## 安全注意事项

- 不要把 `.env` 文件发送给别人。
- 不要把 API Key 发到聊天、群组、截图或 GitHub。
- 不要把 API Key 填入浏览器地址栏或前端代码。
- 如果怀疑密钥泄露，请立即在模型平台撤销并重新创建。
- 当前项目是本地单用户模式；部署到互联网前，还需要登录、权限、HTTPS、限流和云端密钥管理。

## 恢复本地 Mock 模式

如果不想使用真实模型，把 `.env` 中的默认供应商改回：

```text
MODEL_PROVIDER=mock
```

Mock 模式不需要 API Key，也不会产生云端费用。
