## 四、SSE 聊天事件

请求：

```json
{
  "sessionId": "welcome",
  "message": "今天我想记录我们的共同经历。",
  "provider": "deepseek",
  "model": "deepseek-chat"
}
```

| 事件 | 状态 | 返回和前端处理 |
|---|---|---|
| `meta` | 已验证 | 返回 `messageId`、召回数量、协议、最终 provider/model；前端创建临时助手消息 |
| `text` | 已验证 | 返回 `delta`；前端逐段追加文本并保持生成状态 |
| `error` | 已验证 | 返回可识别错误码和消息；前端显示失败原因 |
| `done` | 已验证 | 返回消息、记忆、人格版本及最终 provider/model；前端结束流式状态 |

后端实际流程：

```text
校验会话和模型
→ 保存用户消息到 PostgreSQL
→ breath 检索记忆
→ SSE meta
→ SSE text
→ 保存助手消息
→ hold 保存事件记忆
→ grow 创建成长证据
→ 更新人格版本
→ 保存用户状态
→ SSE done
```

失败时不会伪造成功：存储写入失败返回 `STORAGE_WRITE_FAILED` 或具体数据库错误；模型错误会发送 `error` 和 `done { ok: false }`。
