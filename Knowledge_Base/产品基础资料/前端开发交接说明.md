# Cochpia 前端开发交接说明

更新日期：2026-08-12

## 1. 交接结论

Cochpia 后端核心开发已完成，前端现在可以进入 Workspace 开发。

前端必须消费现有 API Contract，不应重新设计数据库、复制后端业务逻辑或新增未定义接口。

当前本地服务：

- 前端：`http://localhost:5173`
- API：`http://localhost:8787`
- 健康检查：`GET /api/health`
- 就绪检查：`GET /api/ready`
- 版本：`GET /api/version`

当前为个人 Demo 模式：本地 Auth 关闭、Memory 使用本地模式、数据库结构暂不迁移、远程 MCP 和云端部署暂不进行。

## 2. 后端已完成能力

### Runtime / Chat

- Session 创建、读取、修改、归档、置顶、删除
- Message 读取、编辑、删除
- `POST /api/chat/stream`
- `POST /api/chat/regenerate`
- `POST /api/chat/retry`
- `POST /api/chat/cancel`
- SSE `meta`、`text`、`error`、`done`
- SSE Event ID、Heartbeat、断线重连和断点回放
- 当前 Session 的模型、Memory、Personality、Runtime Context 会进入生成链路

### Memory

- `GET /api/memories`
- `POST /api/memories`
- `GET /api/memories/:id`
- `PATCH /api/memories/:id`
- `DELETE /api/memories/:id`
- `GET /api/memories/export`
- `POST /api/memories/:id/revoke`
- `POST /api/memories/batch`
- `GET /api/memory/overview`
- `GET /api/memory/dream`

撤回是软撤回，默认列表隐藏已撤回记录，导出仍保留完整数据。

### Personality / Growth

- `GET /api/personality`
- `GET /api/personality/history`
- `GET /api/personality/audit`
- `POST /api/personality/rollback`
- `GET /api/growth/evidence`
- `GET /api/growth/evidence/:id`
- `PATCH /api/growth/evidence/:id`
- `POST /api/growth/evidence/batch`

成长证据默认是 `draft`。只有用户确认后才会应用人格变化，并生成可审计的人格版本；重复确认不会重复修改人格。

### Task

- `GET /api/tasks`
- `POST /api/tasks`
- `PATCH /api/tasks/:id`
- `DELETE /api/tasks/:id`

任务状态：

```text
open
in_progress
completed
cancelled
```

支持 `sessionId`、`dueAt`、关键词、状态和逾期筛选。完成任务会记录 `completedAt`。

### Sync

- `GET /api/sync?limit=100`
- `GET /api/sync?cursor=<cursor>&limit=100`

返回：

```json
{
  "version": 1,
  "syncedAt": "ISO timestamp",
  "changes": [],
  "nextCursor": "opaque cursor",
  "hasMore": false,
  "limit": 100
}
```

同步实体包括：`session`、`message`、`memory`、`task`、`evidence`、`personality_audit`、`personality`。

前端只保存并回传 `nextCursor`，不要解析 cursor 内部格式。

### Provider

- `GET /api/models`
- `GET /api/sessions/:id/model`
- `PATCH /api/sessions/:id/model`
- `POST /api/models/:provider/test`

模型 API Key 只存在服务端环境变量，不能进入浏览器、前端 Bundle 或 state 数据。

SSE `meta` 和 `done` 会返回最终实际使用的 `provider` 与 `model`。

### MCP

- `POST /mcp`
- 独立 MCP 服务位于 `services/memory-mcp/`
- 当前个人 Demo 默认 `MEMORY_MODE=local`
- MCP 不可用时后端会降级到本地 Memory
- 远程 MCP 尚未云端部署

## 3. 前端开发边界

前端负责：

- Workspace 布局、主题、响应式和交互状态
- Session、Message、Memory、Personality、Growth、Task 的展示
- SSE 消费、断线重连提示和生成状态
- Provider 设置和连接测试结果展示
- Sync cursor 的保存与定期同步
- loading、empty、error、disabled、selected、success 状态

前端禁止：

- 直接连接数据库或 MCP 数据库
- 在浏览器保存模型 API Key、数据库连接字符串或 MCP Token
- 在前端自行修改人格、记忆或成长证据
- 复制 Memory、Personality、Growth、Task 的业务规则
- 自行拼接或解析供应商原始响应格式
- 新增后端接口前绕过 API Contract
- 修改数据库结构
- 执行真实数据库迁移

## 4. 当前前端已有基础

当前 `client/src/main.jsx` 和 `client/src/styles.css` 已包含：

- React/Vite Workspace
- Cobalt / Paper 主题切换
- 三栏桌面布局和移动端响应式布局
- Session 列表与新建会话
- SSE 聊天展示和断线恢复
- Message 编辑、删除
- Provider 选择、模型设置和连接测试
- Memory 概览
- Personality 趋势和版本差异
- Growth 证据时间线
- Task 面板、创建和完成任务
- Sync cursor 自动同步
- Auth 页面和错误边界

前端下一步应优先进行组件拆分、Workspace 视觉统一、移动端体验和真实浏览器验收，而不是重写后端。
